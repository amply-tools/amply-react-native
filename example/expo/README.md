# `example/expo` — the Amply sample under Expo

This app renders **nothing of its own**. Every screen, control, log row and launch-contract
behaviour comes from `example/shared`, the same module `example/bare` mounts. What each control
must do is specified once, in the KMP repo:

> **`multiplatform-library-template/samples/SAMPLE_APP_SPEC.md`**

## What is host-specific, and where it lives

| File | What it contributes |
|---|---|
| `app/index.tsx` | mounts `<AmplySampleProvider><SampleTabs/></AmplySampleProvider>`. That is the whole file. |
| `app/_layout.tsx` | expo-router's navigator, the splash hand-off, the status-bar style |
| `app/promo/[id].tsx` | the route a campaign deeplink lands on — expo-router matches by path, so it has to exist |
| `src/sampleConfig.ts` | appId, per-platform API keys, the `expo` channel label, the scheme |
| `app.json` | app identity, the URL scheme, the config plugins |
| `metro.config.js` | the shared module's alias, and the single-copy pinning below |
| `plugins/withFmtCpp17.js` | re-applies the `fmt` C++17 pin to the Podfile `prebuild` regenerates |

`example/bare` is the same app with `react-navigation` swapped for expo-router and its own
`SafeAreaProvider`; expo-router already renders one. If a screen differs between the two, that is
a defect in the host boundary, not a platform difference.

## Running it

```bash
yarn install
npx expo prebuild --clean     # regenerates ios/ and android/ — both are gitignored
npx expo run:ios              # or: npx expo run:android
```

`yarn` and not `npm`: the workspace links (`link:../shared`, `link:../..`) are yarn's protocol.

## Configuration

**`app.json` is the only config Expo reads.** There used to be an `expo.config.js` next to it
listing three plugins — including the `fmt` fix — and Expo never read a line of it: the filenames
it resolves are `app.config.ts`, `app.config.js`, `app.json` and `app.config.json`, in that order,
and `expo.config.js` is none of them. `npx expo config --type public` printed `plugins: []` the
whole time. It has been deleted and its contents folded into `app.json`; check that command's
output rather than the file you edited if a plugin ever seems not to run.

`plugins/withFmtCpp17.js` **must stay listed.** fmt 11 (vendored by React Native) fails under
Xcode 26's clang with consteval enabled, and building the `fmt` pod as C++17 flips fmt's own
detection off. `example/bare` pins it directly in its checked-in `Podfile`; here the Podfile is
regenerated by every `prebuild`, so the pin is a config plugin instead. Its removal has to be a
deliberate, version-justified change.

## Metro: one copy of React Native

The SDK repo root carries its own `node_modules/react-native` (a devDependency of the library),
and metro resolves a module by walking up from the importing **file** — so everything under
`example/shared` found that copy rather than this app's, measurable without running anything:

```
$ node -e "console.log(require.resolve('react-native/package.json', {paths:['../shared/src']}))"
…/react-native-sdk/node_modules/react-native/package.json      # 0.81.4 — the library's
$ node -e "console.log(require.resolve('react-native/package.json', {paths:['.']}))"
…/example/expo/node_modules/react-native/package.json          # 0.81.5 — this app's
```

Two React Native instances share no view-config registry and the app dies on its first `<Text>`
with *"View config getter callback for component `RCTText` must be a function"*. `extraNodeModules`
does not fix it — that map is consulted only when resolution **fails**, and here it succeeds, on
the wrong copy. `metro.config.js` pins the singletons with `resolveRequest` instead. Expo's default
resolver has the same hole; nothing in `expo/metro-config` closes it.

## Deeplinks

The registered scheme is **`amplyexpo://`** — its own, exactly as `example/bare` registers
`amplybare://`. A shared `amply://` would resolve to whichever of the two the OS picked when both
are installed, which makes every deeplink test and every screenshot ambiguous.

```bash
# lands on app/promo/[id].tsx
xcrun simctl openurl booted "amplyexpo://promo/summer"
adb shell "am start -a android.intent.action.VIEW -d 'amplyexpo://promo/summer'"
```

Campaign deeplinks delivered by the SDK arrive through `addDeepLinkListener` and are reported on
the **Campaigns** tab, whatever their scheme; the route above is only what the OS opens.

## Deterministic screenshots

The launch contract (SAMPLE_APP_SPEC.md §7) travels on the same scheme. **Use the empty path:**
expo-router routes by path, so `amplyexpo://snapshot?…` would land on its not-found screen —
`example/bare` has no router and no such constraint, which is the one place the two commands differ.

```bash
# iOS simulator
xcrun simctl openurl booted "amplyexpo:///?amplySnapshot=inspect.properties&amplySeed=1"

# Android — the & must survive BOTH shells, so quote the URL for the device's shell too
adb shell "am start -a android.intent.action.VIEW \
  -d 'amplyexpo:///?amplySnapshot=inspect.properties&amplySeed=1'"
```

The app switches to the named tab, seeds deterministic state through real SDK calls, and raises the
`amply.snapshot.ready` marker once the screen has settled. Both parameters are inert when absent.
Screen ids are `SNAPSHOT_TARGETS` in `example/shared/src/launchContract.ts`.

## Parity

```bash
bash ../../scripts/check-sample-parity.sh
```

It asserts that `app/index.tsx` imports `@amply/sample-shared` before it checks a single control
id — the module sits on both examples' metro search paths, so every id in it satisfies a grep for
this example whether or not this example renders it. That green was reported once, while this file
was still building its own `ScrollView`.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `View config getter callback for component 'RCTText'` | two React Natives — see *Metro* above |
| `consteval` errors in `format-inl.h` | the `fmt` plugin is not in `app.json` → `plugins` |
| A plugin "does not run" | check `npx expo config --type public`, not the file you edited |
| `TurboModule 'Amply' not found` | `npx expo prebuild --clean` and rebuild; autolinking reads `react-native.config.js` |
| Metro serving stale files | `watchman watch-del-all && npx expo start --clear` |
